# Application Knowledge

Application Knowledge is organized primarily by **application type**.

## Approved Application Types

- [Web Applications](web/README.md): Browser-based interfaces and web application systems
- [Desktop Applications](desktop/README.md): Locally installed and desktop-oriented software
- [Mobile Applications](mobile/README.md): Applications designed for mobile operating systems
- [Services & APIs](services-apis/README.md): Backend services, application interfaces, and service endpoints
- [Command-Line Applications](command-line/README.md): CLI utilities, scripts, and automation tools
- [Embedded Applications](embedded/README.md): Software operating within dedicated or constrained devices
- [Other & Specialized Applications](other-specialized/README.md): Applications outside the established categories

## Organizational Principles

- **Application type** is the primary navigation classification.
- Application architecture, execution environment, technology stack, communication interface, and security characteristics are distinct dimensions, not additional approved root directories.
- Application types may overlap; a larger application system can contain components of different types. Each concept should have a canonical location, with related concepts linked instead of duplicated.
- Shared, domain-independent concepts should be referenced from Foundations or their canonical locations.
- Cross-domain relationships are represented through the knowledge graph.
- Deeper application-specific classifications remain undefined until approved.
